# E-means with cost-based revival, one batch at a time

[didactic_e_means.py](didactic_e_means.py) is a standalone, commented example of
the main training loop in [E-Means: Scaling Laws for Mini-Batch
K-Means](https://arxiv.org/abs/2611.09501). It imports no Faiss E-means machinery.
Faiss provides a synthetic NumPy dataset; all vector arithmetic, assignments,
statistics and random training draws use CPU Torch in float32, without autograd.

Run it with Python, PyTorch and Faiss installed:

```bash
python contrib/e_means/didactic/didactic_e_means.py
```

The script takes no arguments. Its eight numbered stages correspond to the
sections below; the assignment chapter explains the search helper separately.
Change the constants at the top to explore other sizes. The earlier mass-based
example is preserved in [didactic_e_means_mass_revival.py](didactic_e_means_mass_revival.py)
and its [walkthrough](didactic_e_means_mass_revival.md).

## 1. Create training and test data

[Source: CPU settings and dataset](didactic_e_means.py#L20-L33).

```python
rng = torch.Generator(device="cpu").manual_seed(0)
n, d, k, epochs = 50_000, 32, 128, 3
dataset = SyntheticDataset(d=d, nt=n, nb=0, nq=2_000, seed=1234)
train = torch.from_numpy(dataset.get_train())
test = torch.from_numpy(dataset.get_queries())
```

`SyntheticDataset` creates a nonlinear, low-dimensional distribution embedded
in a larger vector space. The example uses 50,000 training vectors in 32
dimensions, 128 centroids, three epochs and 2,000 separate test vectors.

`get_train()` supplies the clustering data; `get_queries()` supplies the test
data. Both come from the same synthetic distribution. Test vectors never enter
the training loop. No database vectors or nearest-neighbor ground truth are
needed. One seeded Torch generator controls initialization, permutations and the
initial split axes. Later axes are learned from the assigned rows.

Faiss contrib: the caller supplies data generated by [SyntheticDataset.__init__](../../datasets.py#L89-L105); [Emeans._prepare_input](../e_means_torch.py#L344-L354) resolves the input representation and backend.

## 2. Choose the batch size and EMA step together

[Source: coupled recipe](didactic_e_means.py#L36-L45).

```python
raw_batch = 0.00439175 * k**0.134749 * n**0.876473 * epochs**0.813344
batch_size = min(2 ** round(math.log2(raw_batch)), n // 2)
alpha0 = 0.8244 * k**-0.4617 * batch_size**0.9003 * n**-0.4498 * epochs**-0.1057
alpha0 = min(1.0, max(1e-4, alpha0))
steps_per_epoch = math.ceil(n / batch_size)
total_steps = epochs * steps_per_epoch
```

E-means couples the batch size to the initial update weight. The example uses
the fitted **quality** recipe shipped in Faiss:

$$
B \approx 0.00439175\,k^{0.134749}n^{0.876473}T^{0.813344},
$$

rounded to a power of two and capped at half the training set, followed by

$$
\alpha_0 = 0.8244\,k^{-0.4617}B^{0.9003}n^{-0.4498}T^{-0.1057},
$$

clamped to $[10^{-4},1]$. Here $n$ is the training size, $k$ the number
of centroids and $T$ the epoch budget. These are empirical fits; the shipped
coefficients differ from the paper's Table 2. They are not optimality guarantees
for this small synthetic experiment.

Faiss contrib: [_resolve_recipe](../base.py#L141-L161) resolves the batch size and [_step_law](../base.py#L79-L89) computes the initial EMA step.

## 3. Initialize positions, sums and masses

[Source: initial state](didactic_e_means.py#L98-L113).

```python
initial_rows = torch.randperm(n, generator=rng)[:k]
centroids = train[initial_rows].clone()
mass = torch.full((k,), 2**-16)
ema_sums = centroids * mass[:, None]
# R_j estimates removal cost; U_j estimates N_j * covariance_j * axis_j.
removal = torch.zeros(k)
oja = torch.zeros(k, d)
axes = torch.randn(k, d, generator=rng)
axes /= axes.norm(dim=1, keepdim=True)
```

Sample distinct training rows for the initial centroids. Maintain the EMA
state and the direction estimates below:

| Code | Meaning | Shape |
|---|---|---|
| `ema_sums` | Exponentially weighted vector sums $S_j$ | $k\times d$ |
| `mass` | Exponentially weighted counts $N_j$ | $k$ |
| `centroids` | Positions $c_j=S_j/N_j$ | $k\times d$ |
| `removal` | EMA removal penalties $R_j$ | $k$ |
| `oja` | Covariance-vector EMA $\mathbf U_j$ | $k\times d$ |
| `axes` | Unit split directions $u_j$ | $k\times d$ |

Initialize $N_j=2^{-16}$ and $S_j=N_jc_j$. This small positive mass
keeps every initial position defined and gives the first assigned rows a large
influence. Initialize $R_j$ and $\mathbf U_j$ to zero, and draw random unit
axes. A zero removal cost makes an unused centroid a revival candidate.

Faiss contrib: [Emeans._train_rows](../e_means_torch.py#L1218-L1468) samples initial rows and [Emeans.begin](../e_means_torch.py#L713-L766) initializes centroid positions and EMA masses.

## 4. Shuffle once per epoch

[Source: epoch permutation](didactic_e_means.py#L116-L120) and
[batch iteration](didactic_e_means.py#L127-L128).

```python
for epoch in range(epochs):
    order = torch.randperm(n, generator=rng)
```

Each epoch generates a new permutation and visits every training row once.
The final, potentially shorter batch is included. This example deliberately
uses integer epochs and keeps the whole dataset in RAM.

Faiss contrib: [Emeans._train_rows](../e_means_torch.py#L1218-L1468) controls permutations and batch iteration using [_epoch_seed](../base.py#L192-L202).

## Assignment: finding the nearest centroid

[Source: exhaustive assignment helper](didactic_e_means.py#L48-L67).

```python
distances = (
    rows.square().sum(1, keepdim=True)
    + centroids.square().sum(1)[None, :]
    - 2 * rows @ centroids.T
)
labels = distances.argmin(1)
```

For each row $x$, find the nearest current centroid by squared L2 distance:

$$
a(x)=\arg\min_j\|x-c_j\|^2.
$$

`assign()` evaluates every candidate using
$\|x\|^2+\|c\|^2-2x\cdot c$. This needs a $B\times k$ distance
matrix, rather than a $B\times k\times d$ array of differences. There is
no IVF or quantization. Assignment is exhaustive float32 computation, subject
to floating-point rounding. Ties go to the first centroid index.

The centroids stay fixed throughout this call. Updating them happens only after
all the batch's labels and statistics have been computed. With $B$ rows, $k$
centroids and $d$ dimensions, the search takes $O(Bkd)$ arithmetic and stores
$Bk$ float32 distances. For the default example, the distance table is only
128 KiB. At millions of centroids, storing that whole table becomes impractical.

Faiss's native Torch implementation searches blocks of centroids and keeps a
running winner per row. It also prepares centroid norms once for the search;
the query norm is common to all candidates and can be added after selecting
the winner. The NumPy implementation calls `faiss.knn` for exhaustive search.
On supported GPUs, the Torch trainer can select Triton or CuTe assignment
kernels. Hardware, dtype and dimensions determine the automatic selection.

| Contrib route | Search implementation |
|---|---|
| NumPy input | [NumpyEmeans._assign_rows](../e_means.py#L418-L433) calls `faiss.knn` |
| Native Torch | [TorchBackend.assign](../torch_backend.py#L151-L221) searches centroid blocks |
| Triton | [TritonBackend.assign](../torch_backend.py#L371-L393) dispatches to Triton kernels |
| CuTe | [CuteBackend.assign](../torch_backend.py#L535-L550) dispatches to CuTe kernels |

This version also requests the second-nearest alternative before the last pass.
Mask out the winner, find the next winner, and recompute both squared distances
by direct differences. The nonnegative gap is

$$
\Delta(x)=D_2(x)-D_1(x).
$$

If the nearest centroid disappeared while all other positions stayed fixed,
its rows would fall back to their second choice. The sum of these gaps is
therefore the removal penalty under that fixed centroid table. Distinct
centroid IDs with identical positions give a zero gap, which is useful for
identifying redundant centroids. Float32 rounding can make the recomputed
gap slightly negative; the script clamps it to zero.

Evaluation and the final pass request only the nearest centroid. Production
closing with revival may additionally need second-nearest labels; freezing
revival in this example's last pass avoids those labels and their bookkeeping.

The EMA loop consumes labels and per-cluster statistics. An approximate search
could restrict the candidates, for example with IVF, while keeping the EMA
formulas; it would change assignments and the resulting centroids. This example
always visits every candidate. Its `mse()` helper also uses exhaustive search,
so evaluation does not depend on an approximate training index.

Faiss contrib: [Emeans._assign_rows](../e_means_torch.py#L691-L711) dispatches assignment, and [select_backend](../torch_backend.py#L584-L635) selects the execution backend.

## 5. Collect batch statistics

[Source: assignment](didactic_e_means.py#L48-L67),
[batch statistics](didactic_e_means.py#L70-L75), and their
[use in the training loop](didactic_e_means.py#L130-L138).

```python
sums = torch.zeros(k, d)
sums.index_add_(0, labels, rows)
counts = torch.bincount(labels, minlength=k).float()
return sums, counts
```

`batch_statistics()` collects

$$
s_j=\sum_{x:a(x)=j}x,\qquad n_j=\sum_x \mathbf{1}_{a(x)=j}.
$$

`index_add_` accumulates vector sums and `bincount` accumulates counts. Reported
distances are recomputed from direct differences to the selected centroids.

[Source: revival batch statistics](didactic_e_means.py#L78-L86).

```python
residuals = rows - centroids[labels]  # Measured BEFORE the centroid update.
projections = (residuals * axes[labels]).sum(1, keepdim=True)
directions = torch.zeros(k, d)
directions.index_add_(0, labels, projections * residuals)
costs = torch.zeros(k)
costs.index_add_(0, labels, gaps)
return directions, costs
```
Before moving centroids, `revival_statistics()` computes residuals $y=x-c_j$
and projections $p=y\cdot u_j$, then accumulates

$$
r_j=\sum_{x:a(x)=j}\Delta(x),\qquad
\mathbf v_j=\sum_{x:a(x)=j}(y\cdot u_j)y.
$$

The first sum measures how expensive it would be to remove cluster $j$.
The second is a covariance-vector product without storing a covariance matrix.
Both use the same pre-update centroids and axes as the batch's assignment.
They are skipped during the final pass, when revival is disabled.

Faiss contrib: [Emeans._accumulate_core](../e_means_torch.py#L838-L943) collects batch contributions through [TorchBackend.accumulate](../torch_backend.py#L223-L247).

## 6. Update the sum-and-count EMAs

[Source: cosine schedule and EMA update](didactic_e_means.py#L140-L154).

```python
cosine = 0.5 * (1 + math.cos(math.pi * step / total_steps))
alpha = alpha0 * (0.1 + 0.9 * cosine)
# Normalized power iteration (Oja direction): a covariance-vector
# product needs only a vector per cluster, not a (d, d) matrix.
if not final_pass:
    oja = (1 - alpha) * oja + alpha * batch_oja
    removal = (1 - alpha) * removal + alpha * batch_removal
    norms = oja.norm(dim=1, keepdim=True)
    axes = torch.where(norms > 0, oja / norms.clamp_min(1e-12), axes)
ema_sums = (1 - alpha) * ema_sums + alpha * sums
mass = (1 - alpha) * mass + alpha * counts
centroids = ema_sums / mass[:, None]
step += 1
```

At update $t$, out of $M$ total updates, use cosine decay:

$$
\alpha_t=\alpha_0\left[0.1+0.9\frac{1+\cos(\pi t/M)}2\right].
$$

The updates start at $t=0$, so the last update approaches the floor rather
than landing exactly on it. Update every cluster with

$$
S_j\leftarrow(1-\alpha_t)S_j+\alpha_ts_j,\qquad
N_j\leftarrow(1-\alpha_t)N_j+\alpha_tn_j,\qquad
c_j\leftarrow S_j/N_j.
$$

This is an EMA of **sums and counts**, whose ratio defines the position.
For an occupied cluster, the equivalent centroid update is

$$
c_j^{\mathrm{new}}=c_j^{\mathrm{old}}+
\frac{\alpha_t n_j}{N_j^{\mathrm{new}}}
\left(\frac{s_j}{n_j}-c_j^{\mathrm{old}}\right).
$$

Thus the effective movement depends on the cluster's current batch count and
historical mass. If a cluster receives no rows, both its sum and mass decay by
the same factor, keeping its position unchanged.

Before the last pass, update the revival statistics with the same EMA weight:

$$
R_j\leftarrow(1-\alpha_t)R_j+\alpha_t r_j,\qquad
\mathbf U_j\leftarrow(1-\alpha_t)\mathbf U_j+\alpha_t\mathbf v_j.
$$

Normalize nonzero $\mathbf U_j$ to get the next axis $u_j$; otherwise retain
its previous direction. This is a streaming normalized power iteration, the
Oja direction estimate used here. For an approximately stationary cluster,
$\mathbf U_j\approx N_j\Sigma_j u_j$, where $\Sigma_j$ is its covariance
about the centroid. Repeated products favor a principal direction of spread.
Only one vector per cluster is stored; no $d\times d$ covariance matrices
or eigendecompositions are needed. The estimate is approximate because the
centroids, assigned populations and axes all change during training.

Faiss contrib: [_scheduled_alpha](../base.py#L205-L209) implements the schedule, and [Emeans._apply_statistics](../e_means_torch.py#L954-L1011) delegates the centroid/mass EMA to [TorchBackend.update](../torch_backend.py#L249-L283).

## 7. Move cheap centroids to split promising donors

[Source: cost-based revival](didactic_e_means.py#L156-L184).

```python
if not final_pass and step % 5 == 0:
    candidates = (removal <= 0) | (removal < 0.3 * removal.quantile(0.5))
    gain = oja.norm(dim=1)
    victims = candidates.nonzero().flatten()
    victims = victims[torch.argsort(removal[victims], stable=True)]
    donors = (~candidates & (mass > 0) & (gain > 0)).nonzero().flatten()
    donors = donors[torch.argsort(gain[donors], descending=True, stable=True)]
    # zip stops when either list is exhausted. Each ID occurs once;
    # no donor can be a victim, so earlier splits cannot affect later ones.
    for donor, victim in zip(donors.tolist(), victims.tolist()):
        center = centroids[donor].clone()
        spread = torch.sqrt(2 * gain[donor] / (math.pi * mass[donor]))
        offset = spread * axes[donor]
        centroids[donor] = center + offset
        centroids[victim] = center - offset
        # Both children inherit half the donor's mass and statistics.
        # Rebuild sums to match their new positions, not the old mean.
        for state in (mass, removal, oja):
            state[donor] /= 2
            state[victim] = state[donor]
        axes[victim] = axes[donor]
        ema_sums[donor] = mass[donor] * centroids[donor]
        ema_sums[victim] = mass[victim] * centroids[victim]
        revivals += 1
```

Every five updates, apply three ideas from production cost-based revival.

### Find cheap victims

Mark clusters with $R_j\leq0$ or $R_j<0.3\operatorname{median}(R)$ as
candidates. Sort them by removal penalty, cheapest first. This uses
**total** penalty, not penalty divided by mass: the question is how much error
removing the whole centroid would add. A small population need not be cheap
if its rows have poor alternatives.

### Choose donors by estimated gain

Exclude **all** removal candidates from the donor pool and require positive
mass. Rank the remaining clusters by $\|\mathbf U_j\|$. When the axis is
aligned with a principal direction, this is approximately the cluster mass
times its variance along that direction. It favors splitting populations
with substantial total spread, rather than simply the largest population.
Pair the cheapest victim with the highest-gain donor, then the next cheapest
with the next highest gain, until either list is exhausted. Each donor is used
once, and donors and victims are disjoint. All choices are made before any
centroid moves. This lets the loop split each pair independently. Stable sorts
resolve equal costs or gains by increasing centroid ID. If either list is
empty, the check makes no changes. Donors with zero estimated gain are skipped.

Under the Gaussian approximation below, the total split gain is proportional
to $(2/\pi)\|\mathbf U_j\|$, so ranking by the norm alone gives the same order.
The threshold is a heuristic; the script does not promise a decrease in MSE
at every revival or explicitly compare the donor's gain to the victim's cost.

### Put the children at Gaussian half-means

For the chosen donor $l$, estimate its directional variance and offset:

$$
\sigma_l^2\approx\frac{\|\mathbf U_l\|}{N_l},\qquad
\delta_l=\sqrt{\frac{2\|\mathbf U_l\|}{\pi N_l}}\,u_l.
$$

The mean of each half of a centered one-dimensional Gaussian is at
$\pm\sigma\sqrt{2/\pi}$. Thus put the children at $c_l+\delta_l$ and
$c_l-\delta_l$. The offset adapts to the cluster's estimated spread, replacing
the mass-based example's arbitrary 1% random displacement.

Give both children half of the donor's $N_l$, $R_l$ and $\mathbf U_l$, and
copy its axis. This keeps the estimated variance ratio $\|\mathbf U_l\|/N_l$
unchanged initially. Reconstruct their EMA sums from the new positions and
masses; discard the victim's old statistics.

Each check can move several disjoint pairs, as in production cost-based
revival. Revival remains disabled during the final pass, so the final sums refer to stable cluster identities.
This omits production's split-related closing reassignment. The example also
omits repairs for children that become identical after low-precision rounding.

Faiss contrib: [Emeans._choose_splits](../e_means_torch.py#L380-L440) chooses revival pairs and [Emeans._apply_splits](../e_means_torch.py#L531-L547) applies them; default cost-based selection is in [_EmeansBase._choose_removal_splits](../base.py#L279-L295).

## 8. Finish with ordinary last-pass means

[Source: last-pass totals](didactic_e_means.py#L121-L138) and
[final means](didactic_e_means.py#L196-L206).

```python
occupied = final_counts > 0
centroids[occupied] = final_sums[occupied] / final_counts[occupied, None]
```

During the last pass, collect `final_sums` and `final_counts` without EMA
weighting. At the end, replace each occupied centroid with their ratio. Keep
the positions of empty clusters.

These assignments were made against **moving** centroids as batches arrived.
The final means therefore differ from a Lloyd iteration, which assigns a whole
pass against one fixed centroid table before updating it. The finalization
removes exponential weighting from the last pass's assigned vectors; it does
not perform another assignment pass.

The [evaluation helper](didactic_e_means.py#L89-L95),
[epoch log](didactic_e_means.py#L186-L193), and
[final log](didactic_e_means.py#L201-L206) report three clearly distinguished errors:

- **Moving train MSE:** batch errors against the pre-update centroids, averaged
  over the epoch.
- **Fresh train MSE:** exhaustive reassignment of training rows to the final
  centroids, measured only after finalization.
- **Test MSE:** exhaustive assignment of separate test rows to the current or
  final centroids.

All are mean squared L2 distance **per vector**, without dividing by dimension.
Evaluation never changes the centroids.

Faiss contrib: [Emeans._start_epoch](../e_means_torch.py#L768-L786) allocates final-pass totals, [Emeans._apply_statistics](../e_means_torch.py#L954-L1011) accumulates them, and [Emeans.finalize](../e_means_torch.py#L1043-L1077) computes the means.

## What this example simplifies

The sum-and-count EMA, coupled recipe, cosine schedule and last-pass means
show the core E-means loop. Revival keeps the removal-cost criterion, shared
EMAs, Oja donor ranking and Gaussian half-mean placement. It pairs all eligible victims with distinct donors and freezes revival
during the last pass to avoid split
bookkeeping. The resulting numbers should not be presented as a reproduction
of the paper or of current Faiss.

The code has one resident dataset, one CPU process and exhaustive assignment.
It has no class hierarchy, lifecycle hooks, kernels, GPU code, distributed
collectives or SSD pipeline. The largest assignment temporary contains
`batch_size * k` float32 values. Evaluation and initialization are included in
the example's work; the printed elapsed time starts after initialization and
includes subsequent evaluations.

Faiss contrib: [Emeans._train_rows](../e_means_torch.py#L1218-L1468) orchestrates the optimized training loop, and [Emeans._close_split_centroids](../e_means_torch.py#L637-L689) handles closing assignments affected by revival.
